The route component takes a component and renders it when the Browser URL matches the url property.

:::note

Note: this component should only be used with vanilla and Stencil JavaScript projects. For Angular projects, use [`ion-router-outlet`](router-outlet.mdx) and the Angular router.

:::

## Catch-all Routes {/* #catch-all-routes */}

:::note

Catch-all routes are supported starting in Ionic v9.1. In earlier versions, `url="/:any"` can be used to catch paths whose first segment does not match another route. Unknown paths below a route that does match, such as `/admin/settings`, still render that route.

:::

A `url` that ends in `*` is a catch-all route. It matches any remaining path, which is useful for showing a "not found" page. The part of the path matched by `*` is passed to the component as the `pathMatch` property, without a leading `/`.

```html
<ion-router>
  <ion-route url="/" component="page-home"></ion-route>
  <ion-route url="/admin" component="page-admin"></ion-route>
  <ion-route url="/admin/users/:id" component="page-admin-user"></ion-route>
  <ion-route url="/admin/*" component="page-admin-not-found"></ion-route>
  <ion-route url="*" component="page-not-found"></ion-route>
</ion-router>
```

With these routes:

| Path                  | Renders                | `pathMatch`    |
| --------------------- | ---------------------- | -------------- |
| `/admin`              | `page-admin`           |                |
| `/admin/users/1`      | `page-admin-user`      |                |
| `/admin/settings`     | `page-admin-not-found` | `settings`     |
| `/admin/users/1/edit` | `page-admin-not-found` | `users/1/edit` |
| `/settings`           | `page-not-found`       | `settings`     |

The component reads `pathMatch` like any other property:

### Matching Priority {/* #matching-priority */}

Without a catch-all, a route that has a `url` and no child routes also matches paths that have extra segments after its `url`. Routes with an empty `url`, such as `/` or a default child route, only match exactly. When a catch-all route matches the path, routes that only match by ignoring extra segments are no longer considered, even if another route wins.

When a catch-all route and a route without a catch-all both match the whole path, the route with more fixed segments wins. A fixed segment is one that is not a parameter, such as `admin`. If they have the same number, the route without the catch-all wins.

Using the routes from the example above:

| Path                  | Without catch-alls | With catch-alls        | Why                                                                                           |
| --------------------- | ------------------ | ---------------------- | --------------------------------------------------------------------------------------------- |
| `/admin`              | `page-admin`       | `page-admin`           | `/admin` and `/admin/*` both have one fixed segment, so the route without the catch-all wins. |
| `/admin/users/1`      | `page-admin-user`  | `page-admin-user`      | `/admin/users/:id` has more fixed segments than `/admin/*`.                                   |
| `/admin/settings`     | `page-admin`       | `page-admin-not-found` | `page-admin` only matched by ignoring `settings`, so the catch-all wins.                      |
| `/admin/users/1/edit` | `page-admin-user`  | `page-admin-not-found` | `page-admin-user` only matched by ignoring `edit`, so the catch-all wins.                     |
| `/settings`           | No match           | `page-not-found`       | No other route matches.                                                                       |

When more than one catch-all route matches, the one with the most fixed segments wins. Segments from parent routes count toward this total, so a catch-all route nested inside another route can handle unknown paths below it.

Redirects run before routes are matched. A redirect from `*` applies to every path, so `<ion-route-redirect from="*">` takes precedence over `<ion-route url="*">`.

### Caveats {/* #caveats */}

A catch-all route also matches its own prefix, so `/admin/*` matches `/admin` with `pathMatch` set to an empty string. This differs from [`ion-route-redirect`](route-redirect.mdx), where `from="/admin/*"` does not match `/admin`.

A `*` is only treated as a wildcard when it is the last segment of the `url`. On a route with child routes, the `*` is ignored and the route matches as if its `url` did not end in `*`.

The router sets `pathMatch` on catch-all routes and overwrites any value passed in `componentProps`, so do not pass it there.

If the `component` of a catch-all route is a tab in `ion-tabs`, the tab does not receive `pathMatch`. Instead, nest the catch-all route as a child of the tab's route so it renders in that tab's `ion-router-outlet`:

```html
<ion-route url="/docs" component="tab-docs">
  <ion-route component="page-docs"></ion-route>
  <ion-route url="*" component="page-docs-not-found"></ion-route>
</ion-route>
```

## Navigation Hooks {/* #navigation-hooks */}

Navigation hooks can be used to perform tasks or act as navigation guards. Hooks are used by providing functions to the `beforeEnter` and `beforeLeave` properties on each `ion-route`. Returning `true` allows navigation to proceed, while returning `false` causes it to be cancelled. Returning an object of type `NavigationHookOptions` allows you to redirect navigation to another page.

## Interfaces {/* #interfaces */}

```typescript
interface NavigationHookOptions {
  /**
   * A valid path to redirect navigation to.
   */
  redirect: string;
}
```

```javascript
const dashboardPage = document.querySelector('ion-route[url="/dashboard"]');
dashboardPage.beforeEnter = isLoggedInGuard;

const newMessagePage = document.querySelector('ion-route[url="/dashboard"]');
newMessagePage.beforeLeave = hasUnsavedDataGuard;

const isLoggedInGuard = async () => {
  const isLoggedIn = await UserData.isLoggedIn(); // Replace this with actual login validation

  if (isLoggedIn) {
    return true;
  } else {
    return { redirect: '/login' }; // If a user is not logged in, they will be redirected to the /login page
  }
};

const hasUnsavedDataGuard = async () => {
  const hasUnsavedData = await checkData(); // Replace this with actual validation

  if (hasUnsavedData) {
    return await confirmDiscardChanges();
  } else {
    return true;
  }
};

const confirmDiscardChanges = async () => {
  const alert = document.createElement('ion-alert');
  alert.header = 'Discard Unsaved Changes?';
  alert.message = 'Are you sure you want to leave? Any unsaved changed will be lost.';
  alert.buttons = [
    {
      text: 'Cancel',
      role: 'Cancel',
    },
    {
      text: 'Discard',
      role: 'destructive',
    },
  ];

  document.body.appendChild(alert);

  await alert.present();

  const { role } = await alert.onDidDismiss();

  return role === 'Cancel' ? false : true;
};
```
