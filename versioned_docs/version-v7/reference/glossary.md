<section id="a11y">
  <a href="#a11y">
    <h3>アクセシビリティ</h3>
  </a>
  <a href="https://developer.mozilla.org/en-US/docs/Web/Accessibility" target="_blank">アクセシビリティ</a>（a11y）は、能力に制限がある人々であっても、できるだけ多くの人がコンテンツを利用できるようにする実践です。これには、障害を持つ人々、モバイルデバイスを使用している人々、遅いネットワーク接続の人々が含まれます。コンテンツは、技術が許す限りアクセス可能に開発されるべきです。
</section>

<section id="android-sdk">
  <a href="#android-sdk">
    <h3>Android SDK</h3>
  </a>
  <a href="http://developer.android.com/sdk/index.html" target="_blank">Android SDK</a>は、GoogleのAndroidプラットフォーム向けに開発する開発者のために作られたソフトウェア開発キットです。Androidアプリケーションの構築、テスト、デバッグのためのツールが含まれています。
</section>

<section id="android-studio">
  <a href="#android-studio">
    <h3>Android Studio</h3>
  </a>
  <a href="https://developer.android.com/studio/" target="_blank">Android Studio</a>は、ネイティブAndroidアプリ開発用の公式統合開発環境（IDE）です。
</section>

<section id="autoprefixer">
  <a href="#autoprefixer">
    <h3>Autoprefixer</h3>
  </a>
  <a href="https://github.com/postcss/autoprefixer" target="_blank">Autoprefixer</a>は、手書きのSass/CSSコードにベンダー固有のプレフィックスを追加するツールです。これにより、記述した標準化されたCSSルールがすべての対応ブラウザに適用されます。例えば、様々なブラウザで使用されるすべてのフレックスボックス構文を知る必要がある代わりに、autoprefixerを使えば単に<code>display: flex;</code>と書くだけで、正しいCSSが自動的に挿入されます。
</section>

<section id="bundling">
  <a href="#bundling">
    <h3>バンドリング</h3>
  </a>
  バンドリングは、アプリの依存関係（自分で書いたコードとインストールしたnpmモジュール）を取りまとめ、一つのファイルにコンパイル/トランスパイルするプロセスです。
</section>

<section id="capacitor">
  <a href="#capacitor">
    <h3>キャパシタ</h3>
  </a>
  <a href="https://capacitorjs.com/" target="_blank">キャパシタ</a>は、WebベースのアプリをiOS、Android、Electron、およびWeb上でネイティブに実行できるオープンソースのクロスプラットフォームアプリランタイムです。これらのアプリを「ネイティブプログレッシブウェブアプリ」と呼ぶと便利で、従来のハイブリッドアプリの考え方を超えた次の進化の形を表しています。キャパシタはIonic社によって作成され、現在も積極的に開発・サポートされています。
</section>

<section id="cli">
  <a href="#cli">
    <h3>CLI</h3>
  </a>
  CLI、または<strong>C</strong>ommand-<strong>L</strong>ine <strong>I</strong>nterfaceは、プログラムとやり取りするためのテキストベースのインターフェイスです。Macユーザーに一般的なコマンドラインアプリはTerminalアプリであり、WindowsユーザーはしばしばCommand Promptを使用します。Ionicコミュニティは、しばしばこの用語を<a href="https://ionicframework.com/docs/cli">IonicのCLI</a>を指すために使用します。IonicのCLIは、アプリの本番ビルドの作成、開発サーバーの実行、<a href="https://ionic.io/appflow" target="_blank">Ionic商用サービス</a>へのアクセスなど、さまざまな用途に使用できます。
</section>

{/* cspell:enable */}

<section id="commonjs">
  <a href="#commonjs">
    <h3>CommonJS</h3>
  </a>
  <a href="https://webpack.github.io/docs/commonjs.html" target="_blank">CommonJS</a> は、JavaScript API の標準フォーマットを定義するグループです。彼らは JavaScript モジュールとパッケージの標準を定義しています。
</section>

<section id="cordova">
  <a href="#cordova">
    <h3>Cordova</h3>
  </a>
  <a href="https://cordova.apache.org" target="_blank">Apache Cordova</a> は、標準的な HTML/CSS/JS を完全なネイティブアプリに変換するオープンソースのモバイルアプリケーション開発フレームワークです。カメラや加速度計などのネイティブデバイス機能にアクセスするための JavaScript API を提供します。Cordova には、iOS、Android、Windows Phone 用のウェブアプリをパッケージ化するために必要なビルドツールが含まれています。
</section>

<section id="cors">
  <a href="#cors">
    <h3>CORS</h3>
  </a>
  <a href="https://developer.mozilla.org/en-US/docs/Web/HTTP/CORS" target="_blank">CORS</a>（クロスオリジンリソースシェアリング）は、サーバーがクライアントのウェブ資産へのアクセスを制御するための仕組みです。詳細は <a href="../troubleshooting/cors">CORS FAQ</a> を参照してください。
</section>

<section id="css-variables">
  <a href="#css-variables">
    <h3>CSS変数</h3>
  </a>
  あなたはSassの変数に馴染みがあるかもしれません。<a href="https://developers.google.com/web/updates/2016/02/css-variables-why-should-you-care" target="_blank">CSS変数</a>は同じ機能を提供しますが、ブラウザに組み込まれています。CSS変数はすべての最新ブラウザで利用可能です。
</section>

<section id="decorators">
  <a href="#decorators">
    <h3>Decorators</h3>
  </a>
  デコレーターは関数を返す式です。既存の関数を受け取り、その動作を拡張できます。TypeScript では、<i>クラス</i>や<i>パラメーター</i>も装飾できます。<strong>クラス</strong>を装飾すると、コンストラクターの動作をラップして拡張します。つまり、コンストラクターが呼び出されたときに機能を追加し、元のコンストラクターを返します。<strong>パラメーター</strong>を装飾すると、そのパラメーターに渡される引数をラップします。デコレーターは、引数がメソッドに渡されたときに機能を追加し、元の引数を返します。
</section>

<section id="es5">
  <a href="#es5">
    <h3>ES5</h3>
  </a>
  ES5とは、EcmaScriptの第5版を指します。簡単に言えば、ES5は現在開発者が最もよく知っているJavaScriptのバージョンです。
</section>

<section id="es2015-es6">
  <a href="#es2015-es6">
    <h3>ES2015/ES6</h3>
  </a>
  このバージョンのJavaScriptでは、クラス、モジュール、イテレーター、プロミスなど、多くの新機能が導入されました。最新のブラウザ（Chrome、Safari、Firefox、Edge）はES6を完全にサポートしていますが、古いブラウザでES6の機能を使用するには、<a href="#babel">Babel</a>や<a href="#typescript">TypeScript</a>などのツールがES6コードをES5に<a href="#transpiler">トランスパイル</a>する必要があります。
</section>

<section id="es2016-es7">
  <a href="#es2016-es7">
    <h3>ES2016/ES7</h3>
  </a>
  このバージョンのJavaScriptは、<code>Array.includes</code>や指数演算子など、言語に多くの新機能を追加しました。このJavaScriptのバージョンは、すべてのエバーグリーンブラウザ(Chrome、Safari、Firefox、Edge)で完全にサポートされています
</section>

<section id="es2017-es8">
  <a href="#es2017-es8">
    <h3>ES2017/ES8</h3>
  </a>
  このJavaScriptのバージョンは最新の標準です。現在、新しい公式標準となる前の最終段階にあります。この仕様にはAsync/Await(すべてのエバーグリーンブラウザに既に搭載されている)や共有メモリ/アトミクスが含まれます。
</section>

<section id="genymotion">
  <a href="#genymotion">
    <h3>Genymotion</h3>
  </a>
  Genymotionはサードパーティ製Androidエミュレーターです。非常に高速で、Androidでアプリを素早くテストするのに便利です。詳細はGenymotionの<a href="../developing/tips#using-genymotion-android">リソースセクション</a>をご覧ください。
</section>

<section id="git">
  <a href="#git">
    <h3>Git</h3>
  </a>
  <a href="https://git-scm.com/" target="_blank">Git</a>はコード管理のための分散バージョン管理システムです。これにより、開発チームが同じプロジェクトにコードを貢献しても、コードの競合が起こることなく実現できます。
</section>

<section id="gulp">
  <a href="#gulp">
    <h3>Gulp</h3>
  </a>
  <a href="http://gulpjs.com/" target="_blank">Gulp</a>は、アプリ構築に使えるタスクを実行するためのツールです。一般的なビルド作業には、<a href="#es2015-es6">ES6</a>を<a href="#es5">ES5</a>へのトランスパイル、<a href="#sass">Sass</a>をCSSに変換、コードの縮小、ファイルの連結などがあります。
</section>

<section id="es-modules">
  <a href="#es-modules">
    <h3>ESモジュール</h3>
  </a>
  <a href="https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/import" target="_blank">ESモジュール</a>は、モジュールの概念をネイティブにJavaScriptに導入します。モジュールを使うことで、クラスや変数はもはやグローバルスコープに存在せず、使用するにはプロジェクトに明示的にインポートする必要があります。これにより、コードがどこから来ているのかを理解しやすくなり、機能のモジュール化と区画化が向上します。
</section>

<section id="ionicons">
  <a href="#ionicons">
    <h3>Ionicons</h3>
  </a>
  <a href="https://ionic.io/ionicons/" target="_blank">Ionicons</a>は、Ionicによって使用および作成されたオープンソースのアイコンセットです。1:1のiOSアイコンとMaterial Designアイコン、さらに一般的に使用されるソーシャル/アプリケーションアイコンが含まれています。IoniconsはデフォルトでIonicの配布に含まれていますが、任意のプロジェクトでも使用できます。
</section>

<section id="karma">
  <a href="#karma">
    <h3>Karma</h3>
  </a>
  <a href="https://karma-runner.github.io/latest/index.html" target="_blank">Karma</a>は、アプリのテストを実際のブラウザ内で実行するテストランナーです。任意のテストフレームワークで書かれたテストケースを実際のブラウザで実行します。Karmaは元々Angular 1用に作成されました。
</section>

<section id="module">
  <a href="#module">
    <h3>モジュール</h3>
  </a>
  JavaScriptのモジュールは、小さく独立しており再利用可能なコードの単位で、互いにおよびグローバルスコープから隔離されています。
</section>

<section id="monorepo">
  <a href="#monorepo">
    <h3>モノレポ</h3>
  </a>
  <strong>モノレポ</strong>とは、複数のプロジェクトを含む単一のGitリポジトリです。利点には、より簡単な整理、共有ツールや依存関係、チームメイトとのより良い共同作業が含まれます。
</section>

<section id="livereload">
  <a href="#livereload">
    <h3>ライブリロード</h3>
  </a>
  <strong>ライブリロード</strong>（または <strong>live-reload</strong>）は、アプリに変更が検出されるとブラウザや <a href="../core-concepts/webview">Webビュー</a> を自動的にリロードするツールです。場合によっては、ウィンドウ全体をリロードせずにアプリの一部を置き換えることもできます。詳細は <a href="../cli/livereload">ライブリロードのドキュメント</a> を参照してください。
</section>

<section id="node">
  <a href="#node">
    <h3>Node</h3>
  </a>
  <a href="https://nodejs.org/" target="_blank">Node</a> は、サーバーサイドで JavaScript を記述できるランタイム環境です。Web サービスに使用されるだけでなく、Node は <a href="#cli">Ionic CLI</a> のような開発者向けツールの構築にもよく使われます。
</section>

<section id="npm">
  <a href="#npm">
    <h3>npm</h3>
  </a>
  <a href="https://www.npmjs.com/" target="_blank">npm</a> は <a href="#node">node</a> のパッケージマネージャーです。これにより、開発者は Node モジュールをインストール、共有、パッケージ化することができます。Ionic は npm でインストールでき、多くの依存関係も一緒にインストールされます。
</section>

<section id="observable">
  <a href="#observable">
    <h3>オブザーバブル</h3>
  </a>
  オブザーバブルはイベント（または通知）を発行するオブジェクトです。オブザーバーはこれらのイベントを聴いて、イベントを受信したときに何かを行うオブジェクトです。両者は一緒に、非同期プログラミングに使用できるパターンを作成します。
</section>

<section id="package-id">
  <a href="#package-id">
    <h3>パッケージID</h3>
  </a>
  Appleでは<strong>Bundle ID</strong>、Androidでは<strong>Application ID</strong>と呼ばれる<strong>パッケージID</strong>は、App StoreやPlay Storeに公開されたアプリを識別するために使用されます。それは<a href="https://en.wikipedia.org/wiki/Reverse_domain_name_notation" target="_blank">逆DNS表記</a>でフォーマットされた文字列です。
</section>

<section id="polyfill">
  <a href="#polyfill">
    <h3>ポリフィル</h3>
  </a>
  <a href="https://remysharp.com/2010/10/08/what-is-a-polyfill" target="_blank">ポリフィル</a>は、ブラウザに機能を追加し、ブラウザ間の違いを標準化するコードの一部です。これは<a href="#shim">シム</a>に似ていますが、シムが独自のAPIを持つのに対し、ポリフィルはブラウザの期待されるAPIが使用できるようにします。
</section>

<section id="protractor">
  <a href="#protractor">
    <h3>プロトラクター</h3>
  </a>
  <a href="https://angular.github.io/protractor/#/" target="_blank">プロトラクター</a>はAngularチームによって、またそのために書かれたテストフレームワークです。プロトラクターは、Karmaのようなテストランナーと一緒に使用してエンドツーエンドテストを行うことができます。テストランナーにより、コードの品質を迅速かつプログラム上で検証することが可能になります。
</section>

<section id="sass">
  <a href="#sass">
    <h3>Sass</h3>
  </a>
  Sass は CSS にコンパイルされるスタイルシート言語で、Ionic で使用されています。Sass は CSS に似ていますが、<a href="http://sass-lang.com/documentation/file.SASS_REFERENCE.html#variables_" target="_blank">変数</a>、<a href="http://sass-lang.com/documentation/file.SASS_REFERENCE.html#mixins" target="_blank">ミックスイン</a>、<a href="http://sass-lang.com/documentation/file.SASS_REFERENCE.html#_10" target="_blank">ループ</a>などの追加機能があります。
</section>

<section id="scoped">
  <a href="#scoped">
    <h3>スコープ付きカプセル化</h3>
  </a>
  スコープ付きカプセル化を使用するコンポーネントは、実行時に各スタイルにデータ属性を付加して自動的にCSSをスコープ化します。CSSでスコープ付きセレクターを上書きするには<a href="https://developer.mozilla.org/en-US/docs/Web/CSS/Specificity" target="_blank">より高い特異性</a>のセレクターが必要です。スコープ付きコンポーネントは<a href="https://developer.mozilla.org/en-US/docs/Web/CSS/Using_CSS_variables" target="_blank">CSSカスタムプロパティ</a>を使用してスタイルを適用することもできます。
</section>

<section id="shadow">
  <a href="#shadow">
    <h3>シャドウDOM</h3>
  </a>
  <a href="https://developers.google.com/web/fundamentals/web-components/shadowdom" target="_blank">シャドウDOM</a>は、コンポーネントのDOMおよびスタイルのカプセル化のためのネイティブブラウザソリューションです。これはコンポーネントを周囲の環境から保護します。シャドウDOMコンポーネントの内部要素を外部からスタイルするには、<a href="https://developer.mozilla.org/en-US/docs/Web/CSS/Using_CSS_variables" target="_blank">CSSカスタムプロパティ</a>または<a href="https://developer.mozilla.org/en-US/docs/Web/CSS/::part" target="_blank">CSSシャドウパーツ</a>を使用する必要があります。
</section>

<section id="shim">
  <a href="#shim">
    <h3>シム</h3>
  </a>
  シムは、ブラウザ間でAPIを標準化するコードの一部です。シムは独自のAPIを持つことができ、ブラウザ固有の実装をエンドユーザーから隠します。
</section>

<section id="transpiler">
  <a href="#transpiler">
    <h3>トランスパイラ</h3>
  </a>
  トランスパイルは、実行前にコードをある言語から別の言語に変換するプロセスです。通常、トランスパイラは高レベル言語を別の高レベル言語に変換します。Ionic Frameworkで最も一般的な<em>トランスパイル</em>のタイプは、<a href="#es2015-es6">ES2015/ES6</a>（<a href="#typescript">TypeScript</a>）を<a href="#es5">ES5</a>（従来のJavaScript）に変換することです。
</section>

<section id="typescript">
  <a href="#typescript">
    <h3>TypeScript</h3>
  </a>
  <a href="http://www.typescriptlang.org" target="_blank">TypeScript</a>はJavaScriptのスーパーセットであり、JavaScriptに加えて<a href="http://www.typescriptlang.org/Handbook#basic-types" target="_blank">型宣言</a>や<a href="http://www.typescriptlang.org/Handbook#interfaces" target="_blank">インターフェイス</a>などの追加機能を提供します。IonicはTypeScriptで構築されていますが、Ionicアプリを作成する際にTypeScriptを使用するかどうかは完全に任意です。
</section>

<section id="unit-tests">
  <a href="#unit-tests">
    <h3>ユニットテスト</h3>
  </a>
  ユニットテストおよびユニットテストは、コードの小さな部分が期待通りに動作するかどうかを確認する方法です。ユニットテストフレームワークには、Jasmine、Mocha、QUnitなど多数があります。
</section>

<section id="webpack">
  <a href="#webpack">
    <h3>Webpack</h3>
  </a>
  <a href="https://webpack.github.io/" target="_blank">Webpack</a> は JavaScript モジュールとその他のアセットをまとめます。必要なときにだけ読み込まれる単一または複数の「チャンク」を作成できます。Webpack は、多数のファイルと依存関係を1つのファイルなどにまとめるために使用できます。
</section>

<section id="web-standards">
  <a href="#web-standards">
    <h3>ウェブ標準</h3>
  </a>
  <a href="https://www.w3.org/" target="_blank">ワールドワイドウェブコンソーシアム</a>（W3C）は、ウェブの標準化団体です。業界のリーダーおよび一般の人々が一緒になって<a href="https://www.w3.org/standards/" target="_blank">ウェブ標準</a>を開発します。ウェブ標準は、ウェブプラットフォームを定義するプロトコル、仕様、および技術のセットです。
</section>

<section id="xcode">
  <a href="#xcode">
    <h3>Xcode</h3>
  </a>
  <a href="https://developer.apple.com/xcode/" target="_blank">Xcode</a>は、Appleのオペレーティングシステム（macOS、iOS、watchOS、tvOS）向けのソフトウェア開発用Apple IDE（統合開発環境）であり、他の言語やプラットフォーム向けの拡張機能も利用可能です。
</section>
